# MAISON Restaurant — Backend

REST API ресторана на Django и Django REST Framework. Проект подготовлен по приложенному ТЗ для передачи frontend-разработчикам и дальнейшего подключения Flutter.

## Структура

В проекте **две основные папки**:

- `config/` — настройки Django, корневые маршруты, WSGI и ASGI.
- `restaurant/` — модели, сериализаторы, API, бизнес-логика, админка и тесты. Внутри только обязательная папка `migrations/` с историей схемы базы.

В корне: `manage.py`, зависимости, `.env.example`, `.gitignore`, документация, `seed_demo.py`, схема OpenAPI и файлы Docker. После запуска Python создаёт служебные папки кэша, а при загрузке фотографий появляется `media/`; они не попадают в Git.

## Что работает

- Регистрация с уникальными email и телефоном, JWT-вход, обновление токена, профиль и аватар.
- Категории и меню: поиск, фильтры, сортировка, популярные блюда, пагинация по 12 записей.
- Бронирование гостем или клиентом, список свободных столов, личные брони и отмена.
- Проверка вместимости, рабочего графика, будущей даты и пересечения двухчасовых броней.
- Личная корзина, изменение количества, оформление доставки или самовывоза, история заказов.
- Расчёт суммы на сервере, сохранение названия и цены блюда на момент заказа, очистка корзины.
- Отзывы с модерацией, контактная форма, сведения о ресторане.
- Django Admin и отдельные staff API для бронирований, заказов, отзывов и обращений.
- Ограничение частоты входа, регистрации, бронирования и контактной формы.

## Быстрый запуск на Windows

Рекомендуется **Python 3.12** — на нём проверен проект. Откройте PowerShell в распакованной папке `MAISON_Backend`, где находится `manage.py`.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(50))"
```

Скопируйте полученную строку в `SECRET_KEY` внутри `.env`. Для локального запуска оставьте `DEBUG=True` и `DB_ENGINE=sqlite`.

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe seed_demo.py --with-demo-admin
.\.venv\Scripts\python.exe manage.py runserver
```

Активация виртуального окружения не обязательна: команды выше работают и при запрете `Activate.ps1`. Если Python 3.12 не установлен, сначала установите его.

Открыть:

- Swagger: http://127.0.0.1:8000/api/docs/
- Админка: http://127.0.0.1:8000/admin/
- Меню: http://127.0.0.1:8000/api/v1/menu/
- Схема: http://127.0.0.1:8000/api/schema/

**Локальный демонстрационный администратор:** `demo_admin` / `MaisonDemo!2026`.
Эта учётная запись присутствует только в демонстрационной SQLite-базе архива; её пароль опубликован намеренно для локальной проверки. Не используйте эту базу и этого администратора на публичном сервере.

В архив включена готовая `db.sqlite3`: 5 категорий, 15 блюд, 6 столов, информация о ресторане и один демоотзыв. `seed_demo.py` позволяет восстановить данные после клонирования из GitHub и не дублирует их при повторном запуске. Фотографии не включены: поля `image` возвращают `null`, пока вы не загрузите изображения через админку. Адрес, цены и контакты демонстрационные.

## Передача фронтенду

Передайте ссылку на GitHub и файл `API_GUIDE.md`. Схему `openapi.yaml` можно импортировать в Postman или использовать для генерации клиента. Swagger доступен без авторизации; защищённые запросы требуют access-токен.

Базовый адрес API при локальном запуске: `http://127.0.0.1:8000/api/v1/`.

Frontend на React/Vite: `http://localhost:5173`; также разрешены `http://127.0.0.1:5173` и `http://localhost:3000`. Если адрес отличается, добавьте его в `CORS_ALLOWED_ORIGINS` в `.env` и перезапустите сервер. Не включайте общий доступ CORS для всех сайтов.

Фронтендер может запустить собственную копию backend. Для общего сервера понадобится хостинг: ссылка на GitHub сама по себе API не запускает. Для Android-эмулятора адрес компьютера обычно `10.0.2.2`, для реального телефона — LAN-IP компьютера; добавьте этот адрес в `ALLOWED_HOSTS` и запустите сервер командой `python manage.py runserver 0.0.0.0:8000` в доверенной локальной сети.

## Загрузка на GitHub

Создайте **пустой** репозиторий `MAISON-Backend` без автоматически создаваемых README и `.gitignore`. Выполните из папки проекта:

```bash
git init
git add .
git status
git commit -m "Add MAISON restaurant backend"
git branch -M main
git remote add origin https://github.com/Danieldev066/MAISON-Backend.git
git push -u origin main
```

Если репозиторий принадлежит команде, замените адрес на командный. Если `origin` уже настроен, используйте `git remote set-url origin <URL>` вместо `git remote add`.

Перед коммитом `git status` должен показывать код, миграции и `.env.example`, но не `.env`, `.venv`, `db.sqlite3` и пользовательские изображения. Готовая SQLite-база намеренно исключена из Git; после клонирования используйте миграции и `seed_demo.py`.

python manage.py test restaurant

Проверено на Python 3.12 и SQLite: 34 API-теста, миграции с пустой базы, проверка конфигурации Django, генерация и валидация OpenAPI без предупреждений. Тесты проверяют брони, права доступа, регистрацию/JWT, корзину, заказы, отзывы, ограничения частоты запросов и CORS.

## PostgreSQL и Docker

Для PostgreSQL без Docker задайте в `.env` `DB_ENGINE=postgresql` и параметры `POSTGRES_*`, создайте базу, затем выполните миграции. Схема и код одни для обеих баз. При конкурентном оформлении заказа блокируется корзина, при бронировании — стол; транзакции в SQLite используют режим IMMEDIATE.

Для Docker установите Docker Desktop, создайте `.env` по примеру, замените ключ и пароль БД, затем:

```bash
docker compose up --build -d
docker compose exec web python seed_demo.py
docker compose exec web python manage.py createsuperuser
```

Compose сам запускает PostgreSQL, выполняет миграции и собирает статику. Данные PostgreSQL хранятся в томе, загруженные изображения — в отдельном томе. Контейнер Django работает от непривилегированного пользователя. Docker и PostgreSQL в среде сборки не запускались; перед развёртыванием выполните тесты на выбранной базе.

Для демонстрации с изображениями удобнее локальный `runserver`: при `DEBUG=True` он раздаёт `/media/`. В Docker используется Gunicorn, поэтому для пользовательских изображений требуется отдельная раздача `/media/` через reverse proxy или объектное хранилище. WhiteNoise обслуживает собранную статику админки.

## Перед публичным развёртыванием

Используйте новую PostgreSQL-базу, собственный `SECRET_KEY`, `DEBUG=False`, точные домены `ALLOWED_HOSTS`, CORS и CSRF, HTTPS и своего администратора. Не загружайте демобазу. Запустите `python manage.py check --deploy`, настройте HTTPS-редирект/HSTS для вашего хостинга, раздачу media, резервные копии и общий cache для throttling при нескольких процессах. Встроенный локальный cache ограничивает запросы отдельно в каждом процессе.

Оплата, SMS, email-уведомления, поиск курьеров и реальные платёжные интеграции в ТЗ не предусмотрены и не реализованы. Контактная форма сохраняет сообщение в админке, а не отправляет письмо. Работа по ночному графику через полночь не предусмотрена: администратор задаёт часы внутри одного календарного дня.

ТЗ отмечает, что исходный Figma-макет не был доступен при его составлении. Реализован контракт приложенного ТЗ; соответствие дополнительным экранам Figma отдельно не проверялось.
